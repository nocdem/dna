Explorer API

All endpoints use GET; list endpoints accept a limit of up to 100. A transaction is addressed by its wire id, its intent id or its position height:index. Block lists page with before=<height>, a block’s transactions with from=<index>, and address history with before=<height:index>; each response names the next cursor.

/api/stats
/api/blocks?before=<height>&limit=25
/api/block/<height-or-block-id>?from=<index>
/api/tx/<wire-id | intent-id | height:index>
/api/address/<fingerprint>?before=<height:index>&limit=25
/api/search?q=<term>
/api/governance
/api/tps
/api/paydays?before=<height>&limit=25
/api/payday/<height>?from=<sequence>&limit=100
/api/rewards/<fingerprint>?before=<height:sequence>&limit=25

/api/governance lists every applied chain-configuration vote, hard forks included, in block order, with its effective height and the last reported tip (at most 1000 records). /api/tps returns the throughput of applied transactions for the last minute, the last hour and 24 hourly buckets, measured by block time up to the newest indexed block, plus the next payday, past paydays and an APY estimate.

/api/paydays lists payday totals and recipient counts; /api/payday/<height> lists the actual recipients and amounts. /api/rewards/<fingerprint> returns recorded paid totals, pending rewards and payout history. Follow the returned next cursor exactly. Payout coverage starts at from_height; paid totals are not lifetime totals. On rewards responses, at_height is the source block for pending rewards. Unavailable historical summaries have available: false and null amounts/counts; an unavailable source returns HTTP 503.

An address response carries its balances per token (total, spendable and coin count) as reported by the network. Money fields are decimal strings in base units with eight decimals for NODUS. Preserve integer precision when formatting them. Unknown stats can be null; an unavailable index can return HTTP 503.

Smart contracts (Nodus EVM)

Status: smart contracts run on Nodus EVM, the chain’s own EVM engine. Validators voted it in on 6 October 2026, at block 62,425; it switches on at testnet block 79,757. Until that block nodes refuse every smart-contract command: transactions are not built, because the node does not yet run the EVM rule set, and queries answer that the EVM is not active.

What is different from Ethereum

  • Post-quantum signatures. Transactions are signed with your Nodus identity’s ML-DSA-87 key, not with secp256k1. Your EVM address is the first 32 bytes of the SHA3-512 hash of your public key; nodus-cli evm address prints it.
  • 32-byte addresses. An address is 64 hexadecimal characters, in the ABI as well. A 20-byte Ethereum address padded with zeros is a different account. abi.encodePacked(address) gives 32 bytes, and ecrecover must never be used to authorize an account.
  • No Ethereum tooling. MetaMask, ethers, viem and eth_* JSON-RPC expect 20-byte addresses and are not supported. Use nodus-cli or the web wallet.
  • Fees in NODUS. Every contract transaction pays its fee in NODUS from your coins; a call that fails is still included and still pays. Inside the EVM, 1 NODUS = 1018 wei.
  • Prague rules, without blob and set-code transactions.

Get the compiler. A standard Solidity compiler cuts addresses to 20 bytes, so contracts need the Nodus solc: Solidity 0.8.30 with 32-byte addresses. Code that converts addresses to uint160 or bytes20, calls linked libraries or stores external function types does not compile; port it to uint256 / bytes32.

Download the Nodus solc for Linux x86-64 →
sha256: a09d6486c944a795009f08dbc8210ce2eee2785248f9f5f7edc2aaa9c6934649
It needs glibc 2.34 or newer and a libstdc++ that provides GLIBCXX_3.4.29. Check the file and install the compiler where nodus-cli looks for it:

sha256sum nodus-solc-0.8.30-nodus.addr256-linux-x86_64.tar.gz
tar xzf nodus-solc-0.8.30-nodus.addr256-linux-x86_64.tar.gz
sudo install -m 0755 nodus-solc-0.8.30-nodus.addr256-linux-x86_64/solc-nodus /usr/local/bin/solc-nodus
solc-nodus --version

The version line must contain nodus.addr256. If you install it elsewhere, set NODUS_SOLC or pass --solc-bin <path>. To build it yourself, nodus/tools/evm/solc/build.sh in the source repository clones Solidity v0.8.30, checks the commit, applies our patch and builds the compiler:

cd nodus/tools/evm/solc
JOBS=4 ./build.sh /path/to/work

Compile the example. nodus/tools/evm/examples/NodusToken.sol is a minimal ERC-20-style token: the deployer receives 1,000,000 tokens with 18 decimals. Its bytecode and ABI are already in examples/out/; to rebuild them:

cd nodus/tools/evm/examples
SOLC=/usr/local/bin/solc-nodus ./build.sh

Deploy and call it with nodus-cli. Replace <node-ip> with a Nodus node (client port 4001) and <keys-dir> with your identity directory. From examples/:

nodus-cli evm address --keys <keys-dir>
nodus-cli -s <node-ip> evm deploy --solc NodusToken.sol:NodusToken --keys <keys-dir> --submit <node-ip>:4001
nodus-cli -s <node-ip> evm call <token> "balanceOf(address)(uint256)" <your-evm-address>
nodus-cli -s <node-ip> evm send <token> "transfer(address,uint256)" <to> 1000000000000000000 --keys <keys-dir> --submit <node-ip>:4001

The deploy prints the new contract address (<token>). Amounts are in base units: 1 token = 1018. Before sending, nodus-cli simulates the call and stops if it would fail (--force sends it anyway); it asks before a fee above 50 NODUS (--yes skips the question; --max-fee <raw> refuses anything above your limit instead); --dry-run builds the transaction without sending it. A sender has one pending transaction at a time: the command waits for the receipt. Argument types are uint<M>, int<M>, bool, address, bytes<M>, bytes and string, not arrays or tuples. evm deposit <raw> and evm withdraw <raw> move NODUS into and out of your EVM balance; that balance is needed only for value you send with --value, because fees come from your coins.

Or use the web wallet. The web wallet and Nodus Connect have a smart-contracts panel, in preview, that appears when the connected node runs the EVM rule set. It shows your EVM address and balance, moves NODUS in and out, deploys a contract from its bytecode and ABI (for the example: the files in examples/out/) and opens a contract by its address and ABI to read and write it; every transaction is reviewed before signing.

Receipts and events. Every transaction prints its intent_id, the block that included it, the gas used, its events and, for a deploy, the contract address. To look up a receipt again, or to list a contract’s events (at most 10,000 blocks per query):

nodus-cli -s <node-ip> evm receipt <intent_id>
nodus-cli -s <node-ip> evm logs --from-height <H> --to-height <H> --address <token>

The token’s Transfer events have topic0 0xddf252ad1be2c89b69c2b068fc378daa952ba7f163c4a11628f55a4df523b3ef (filter with --topic0); topics 1 and 2 hold the full 32-byte sender and recipient. Receipts are as reported by the connected node; they are not yet proven against the chain.

On Scan. Type a 64-character EVM address, with or without 0x, into the Nodus Scan search to open its page: the account as the network reports it, its EVM transactions and, for a contract, the transaction that created it and its recent events. A contract transaction’s page has a Smart contract (EVM) section with the action, the result, the gas used, the addresses, any created contract, the number of events and the receipt digest.
