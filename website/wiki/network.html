The resource network

Storage at the core. Bandwidth and compute ahead.

REVIEWED SEPTEMBER 2026EN / TR

Storage · foundation implemented

Nodus stores and replicates signed application records and media, including identity data and encrypted offline messages. Storage is broader than messaging: the planned capacity market will let people buy space for their own files and datasets.

Capacity offers, pricing, retention terms and service-verification rules remain future market work.

Bandwidth · service planned

The direction is a bandwidth service for VoIP and other network traffic. Encrypted endpoint-to-endpoint circuit relay and call signaling exist as building blocks. Live call media and the broader bandwidth market are separate work.

Compute · market planned

The planned market connects compute demand with capacity for STARK proof generation, AI training and other workloads. A C STARK prover and verifier are implemented; scheduling, job trading and the distributed compute service are not launched.

Run a node

Install one node, then give it a role. The same node can hold more than one role: witness, storage node, and later bandwidth and compute.

You need: a Debian or Ubuntu server (x86-64) that stays online, with a fixed public IP, TCP port 4004 open and at least 50 GB of free disk — 150 GB if it will be a storage node.

  1. Install. On the server, run:
    curl -fsSL https://nodusnetwork.io/install-node.sh | sudo bash
    It builds and starts the node and asks only a few questions. Run the same command later to update the node.
  2. Wait until it has caught up. Run sudo nodus-cli status. When the “behind by” line says OK, the node is ready. The first time this takes a while.
  3. Choose a role. In Nodus Connect, open More → Nodus and pick Become a witness or Become a storage node. Connect shows one command: run it on the server, paste what it prints back into Connect and confirm. Your wallet pays the bond.

Choose a role

  • Witness — signs the chain’s blocks. Bond: at least 2,000,000 NODUS. Earns block rewards on paydays, plus a commission you set on the rewards of the people who delegate to it.
  • Storage node — keeps part of the chain’s block archive. Bond: 1,000,000 NODUS. Paid from the Storage pool for the blocks it keeps.
  • Bandwidth and compute — planned, each with its own bond and reward.

One node can be a witness and a storage node at the same time; register each role on its own in Connect. Connect shows the bond in force before you confirm, because witnesses can change it by vote.

The bond comes back when you leave, from More → Nodus → My registered nodes (a witness’s bond after 84 epochs). Turning the server off is not leaving: leave first.

Details for operators

Nothing here is needed for the three steps above.

What runs. A node is three processes — nodus-core (client connections), nodus-storage (the DHT that keeps application records) and nodus-witness (the chain). The nodus-storage program is not what makes a storage node; that role is held by nodus-witness. The older combined server, nodus-server, does the same work in one process and stays available. The CPU needs AVX, BMI2 and ADX, and the clock must be kept in sync (NTP).

The consent. The command Connect shows (sudo nodus-cli consent nodus-consent-v1:…) finds the node’s own key, shows what it will sign and the node’s fingerprint, and asks before it signs. On Connect’s review, check that the fingerprint matches. The wallet owns the role and receives the rewards; the node only gives its consent.

How a storage node is paid. The archive is cut into segments of 17,280 blocks, each held by 3 storage nodes. Every epoch (720 blocks, about an hour) the witnesses ask each storage node for a few random pieces, and the nodes that answer are paid from the Storage pool in proportion to the blocks they keep. A new storage node joins at the next epoch boundary and first fetches the older segments it is given; it earns nothing during that grace — one epoch per segment. A storage node registered under the same owner as the witnesses that check it gets no credit from them. Disk: at least 150 GB free — 50 GB for the node and 100 GB for segment files — and 200 GB recommended.

Block retention. A node decides by its role, with no setting: a witness or a storage node keeps the last 7 paydays (120,960 blocks) plus the link to genesis; a node with no role keeps every block. A storage node never drops a block whose archive file it has not finished, nor the blocks of the period not yet published. Do not add a pruning setting; an operator who wants a full archive sets "retain_blocks": 0. Every node drops the duplicate “seen commit” copy, so chain storage grows more slowly.

Where the applications fit

Connect, Wallet and Identity are applications on the shared foundation. Chain provides the ledger; Scan makes indexed ledger data accessible. Node operation and admission depend on the particular network deployment.
