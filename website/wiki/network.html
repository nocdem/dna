The resource network

Storage at the core. Bandwidth and compute ahead.

REVIEWED SEPTEMBER 2026EN / TR

Storage · foundation implemented

Nodus stores and replicates signed application records and media, including identity data and encrypted offline messages. Storage is broader than messaging: the planned capacity market will let people buy space for their own files and datasets.

Capacity offers, pricing, retention terms and service-verification rules remain future market work.

Bandwidth · service planned

The direction is a bandwidth service for VoIP and other network traffic. Encrypted endpoint-to-endpoint circuit relay and call signaling exist as building blocks. Live call media and the broader bandwidth market are separate work.

Compute · market planned

The planned market connects compute demand with capacity for STARK proof generation, AI training and other workloads. A C STARK prover and verifier are implemented; scheduling, job trading and the distributed compute service are not launched.

Running a node

A Nodus node runs as three processes — nodus-core (client connections), nodus-storage (the DHT that keeps application records) and nodus-witness (the chain) — installed from one tar.gz package with an install script. A node needs at least 50 GB of free disk; a storage node needs more (below). All seven testnet nodes run this layout since 9 October 2026. The older combined server, nodus-server, does the same work in one process and stays available.

Block retention. Since nodus 0.26.5 a node decides by its role, with no setting: a witness or a storage node keeps the last 7 paydays (120,960 blocks) plus the link to genesis; a node with no role keeps every block. A storage node (below) never drops a block whose archive file it has not finished, nor the blocks of the period not yet published. An operator who wants a full archive sets "retain_blocks": 0. Every node drops the duplicate “seen commit” copy, so chain storage grows more slowly.

Run a storage node

Since hard fork HF-6 (block 176,100, 13 October 2026) anyone can run a storage node and be paid for it. A storage node keeps a copy of the chain’s block archive. The archive is cut into segments of 17,280 blocks, each held by 3 storage nodes; every epoch the witnesses ask each storage node for a few random pieces, and the nodes that answer are paid from the Storage pool in proportion to the blocks they keep.

What you need: a Linux x86-64 server that stays online (the CPU needs AVX, BMI2 and ADX), a fixed public IP with TCP port 4004 open, the clock kept in sync, disk: at least 150 GB free — 50 GB for the node and 100 GB for your segment files — and 200 GB recommended (the chain was about 15 GB in mid-October 2026 and grows; the node prunes to 7 paydays once it has a role), and a wallet with 1,000,000 NODUS for the bond plus a small fee. The bond comes back when you leave.

  1. On the server, run the installer:
    curl -fsSL https://nodusnetwork.io/install-node.sh | sudo bash
    It checks the machine, installs the build tools, downloads the latest Nodus source and builds it, writes the settings (the testnet and the seven witnesses below), opens TCP 4004 in the ufw firewall if you agree, and starts the node. It shows this node’s fingerprint at the end. To check the file before running it: download it, compare sha256sum install-node.sh with 538183d39637beda451369aeceb34c90b888958640bda02b789db41f50f1108b, then run sudo bash install-node.sh. Running the same command again later updates the node and keeps its key, settings and chain.

The installer points the node at the testnet with this network file (/etc/nodus-network.json); to set a node up by hand, see the full guide below.

  1. Wait until the node has caught up with the chain: sudo nodus-cli status shows the node’s whole state on one screen — its height against the network’s (“behind by”), the services, its storage / witness registration, disk and memory, and the clock. Do not add a pruning setting: once registered, the node prunes by itself and keeps every block it still needs for its archive files (the guide shows the log lines).
  2. In Nodus Connect, open More → Nodus → Become a storage node. It shows one command with a request code: run it on your node as it is (sudo nodus-cli consent nodus-consent-v1:…). The node finds its own key, shows what it will sign and its fingerprint, and asks before it signs; it then prints a consent. Paste the consent into the page, check that the fingerprint matches and confirm. The wallet locks the bond.

The node joins at the next epoch boundary (720 blocks, about an hour). It first fetches the older segments it is given and earns nothing during that grace — one epoch per segment. Rewards go to the owner wallet on paydays. Stopping the machine is not leaving: leave from the same page first.

The full step-by-step guide, with every command: Running a storage node. The witness list above was read from the chain on 14 October 2026; nodus-cli -s 161.97.85.25 -p 4001 witness prints the current one.

Where the applications fit

Connect, Wallet and Identity are applications on the shared foundation. Chain provides the ledger; Scan makes indexed ledger data accessible. Node operation and admission depend on the particular network deployment.
