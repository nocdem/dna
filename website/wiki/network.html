The resource network

Storage at the core. Bandwidth and compute ahead.

REVIEWED SEPTEMBER 2026EN / TR

Storage · foundation implemented

Nodus stores and replicates signed application records and media, including identity data and encrypted offline messages. Storage is broader than messaging: the planned capacity market will let people buy space for their own files and datasets.

Capacity offers, pricing, retention terms and service-verification rules remain future market work.

Bandwidth · service planned

The direction is a bandwidth service for VoIP and other network traffic. Encrypted endpoint-to-endpoint circuit relay and call signaling exist as building blocks. Live call media and the broader bandwidth market are separate work.

Compute · market planned

The planned market connects compute demand with capacity for STARK proof generation, AI training and other workloads. A C STARK prover and verifier are implemented; scheduling, job trading and the distributed compute service are not launched.

Running a node

A Nodus node runs as three processes — nodus-core (client connections), nodus-storage (the DHT that keeps application records) and nodus-witness (the chain) — installed from one tar.gz package with an install script. All seven testnet nodes run this layout since 9 October 2026. The older combined server, nodus-server, does the same work in one process and stays available.

Block retention. A node either prunes or keeps everything. A pruned node keeps the last 7 paydays (120,960 blocks) plus the link to genesis; an archive node keeps every block. A storage node (below) keeps every block until the files of the archive parts it is given are complete; only then may it prune. Every node drops the duplicate “seen commit” copy, so chain storage grows more slowly.

Run a storage node

Since hard fork HF-6 (block 176,100, 13 October 2026) anyone can run a storage node and be paid for it. A storage node keeps a copy of the chain’s block archive. The archive is cut into segments of 17,280 blocks, each held by 3 storage nodes; every epoch the witnesses ask each storage node for a few random pieces, and the nodes that answer are paid from the Storage pool in proportion to the blocks they keep.

What you need: a Linux x86-64 server that stays online (the CPU needs AVX, BMI2 and ADX), a fixed public IP with TCP port 4004 open, the clock kept in sync, disk for the whole chain (about 10 GB in mid-October 2026, growing) plus your segment files, and a wallet with 1,000,000 NODUS for the bond plus a small fee. The bond comes back when you leave.

  1. Build the programs from the source and install them with the package’s install script.
  2. Point the node at the testnet with this network file (/etc/nodus-network.json, named by "network_file" in /etc/nodus.conf):
{
  "v2_genesis_pin": "a48d1a785500a1cdecd739ecd53ef0e95b1dc4a7a300f49176a7fa25ae176114",
  "persistent_peers": [
    "fd429639366cbc41d98db7603d51166ed5542d2d161cf69ff1ab6dbe80176197@161.97.85.25:4004",
    "16af3eaa620ab5d239ca63abd01943c7b1a8580a3c0204ec8a093bf7992c79df@156.67.24.125:4004",
    "04cdf00b3c37782b7df02fc0f71ba3b74893a60cbb800369d9ee6e97c46dd3ed@156.67.25.251:4004",
    "681c12a60cae6956d1c7a1b8c75b08594961888e0d8319882fee4c94ce77b55f@164.68.105.227:4004",
    "a7b23e52f02af2d2f526d58c741bb405825af8e31d753dc670b9c94cc01d2401@164.68.116.180:4004",
    "6573f74c177c9d97ba784e9607b487125f973f71026931e522051d9ba6fe713a@75.119.141.51:4004",
    "03499d1fae35f9e9aaf60a1c3f18d8c7d1ffa49f2c65bd4b6a531bdf8ef92c21@154.38.182.161:4004"
  ]
}
  1. Start the node and wait until it has caught up with the chain (compare its height with Scan). Do not switch on pruning yet: witnesses ask for old blocks, and until the node has a complete file for every archive part it is given, those blocks can only come from its own chain store. Pruning is fine once the node’s log reports all its parts complete and one more full epoch has passed without errors (the guide shows the exact log lines).
  2. In Nodus Connect, open More → Nodus → Become a storage node. It shows one command with a request code: run it on your node as it is (sudo nodus-cli consent nodus-consent-v1:…). The node finds its own key, shows what it will sign and its fingerprint, and asks before it signs; it then prints a consent. Paste the consent into the page, check that the fingerprint matches and confirm. The wallet locks the bond.

The node joins at the next epoch boundary (720 blocks, about an hour). It first fetches the older segments it is given and earns nothing during that grace — one epoch per segment. Rewards go to the owner wallet on paydays. Stopping the machine is not leaving: leave from the same page first.

The full step-by-step guide, with every command: Running a storage node. The witness list above was read from the chain on 14 October 2026; nodus-cli -s 161.97.85.25 -p 4001 witness prints the current one.

Where the applications fit

Connect, Wallet and Identity are applications on the shared foundation. Chain provides the ledger; Scan makes indexed ledger data accessible. Node operation and admission depend on the particular network deployment.
