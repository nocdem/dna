Applications on shared foundations.

Nodus is the shared infrastructure behind the ecosystem: distributed storage today, expanding toward Storage, Bandwidth, and Compute services and markets. Connect is an application on that network; the native chain supplies the shared ledger.

Nodus is the new brand.

The DNA ecosystem is being rebranded separately from CPUNK. Existing binaries, repository paths, downloads, and service hosts retain their current names during the transition. Connect and Network are release candidates; the chain is on devnet. Nodus / NODUS is planned for testnet.

Nodus Identity

Identity starts with locally generated keys, rather than a phone number or email account. A registered name resolves to cryptographic identity records on the Nodus DHT, so contacts can find you by name.

  1. Create an identity or restore it from your 24-word BIP39 recovery phrase.
  2. Register a name and set up your profile, avatar, and bio.
  3. Use the same identity for contacts, signed public posts, and wallet-address discovery.

The recovery phrase restores key material and derived accounts. It is not a promise that every local file or message can be recovered; retained and synchronized data have their own availability limits.

Nodus Connect

Connect combines private conversations, public social features, and an integrated wallet. Its Flutter interface is backed by a native C engine, with application code for Android, Linux, and Windows.

  • End-to-end encrypted direct and group messages, group-key management, and delivery/read receipts.
  • Voice messages with waveforms, images, videos, and a persistent media upload queue with resume.
  • Offline messages retained for up to seven days, plus message and group synchronization across devices.
  • Profiles, follows, and signed public wall posts. These social posts are public, unlike private chat content.

Feature status: public channels are disabled in the current local application. Voice-call signaling exists in the engine; a complete calling service is not advertised here.

Nodus Wallet

Wallet lives inside Connect and derives accounts from the same recovery phrase. It supports Ethereum, BNB Smart Chain, Solana, TRON, and Cellframe, alongside the native DNAC development chain.

  • Send crypto from a conversation using contact-to-wallet address resolution.
  • Use QR codes for send/receive and review balances and transaction history.
  • Swap through integrated DEX routes. Routing and transaction protection vary by network and provider.

External networks keep their own signing rules and security properties. The app’s post-quantum messaging does not change Ethereum, Solana, or another network’s transaction cryptography.

Nodus Network & Node

Nodus is a resource network with storage as its current foundation. Its DHT holds signed application records, while a media store handles binary content. Replication, discovery, subscriptions, presence, and circuit relay connect this infrastructure to applications.

  • Nodus Node is the server software. The C client SDK exposes storage, lookup, subscription, and transport operations to applications.
  • Nodes replicate records and media. Expiration depends on record type; permanent identity records differ from temporary message queues.
  • The circuit API offers an explicitly encrypted endpoint-to-endpoint mode. Relays still see routing identities; this is not onion routing.

The server can be built and operated independently. Access to a particular running network depends on that deployment’s configuration and admission policy.

Storage: application data and capacity

Implemented storage includes signed records, identity data, offline message buckets, and media replication. The product direction extends this into a market where users can buy storage for their own files and datasets. Capacity offers, retention terms, pricing, and service-verification rules belong to that future market.

Bandwidth: traffic and real-time communication

Encrypted circuit relay and call signaling with per-call key agreement are implemented. VoIP audio transport and a broader bandwidth service remain planned. The media and UDP fast-path design documents have open review work; signaling alone is not a complete calling product.

Compute: proof generation and AI workloads

The project already contains a C STARK prover and verifier. The planned compute market will connect demand for proof generation, AI training, and other compute jobs with capacity. A working prover is a building block; scheduling, resource trading, and the distributed compute service are separate future work.

Nodus Chain & NODUS

The native chain is currently on devnet under the DNAC name. Its C client builds transactions and manages wallet state; BFT witnesses embedded in Nodus maintain the authoritative ledger. DHT identity lookup and witness consensus are separate responsibilities.

  • Transparent UTXO accounting and post-quantum transaction signatures.
  • Hash-linked blocks, state commitments, and commit certificates from witness agreement.
  • Implemented native assets, staking, delegation, epoch settlement, and committee-voted chain parameters; development and integration continue.

Coin name: Nodus. Ticker: NODUS. The rename is planned with testnet; devnet continues as DNAC for now. Nodus has a brand separate from CPUNK.

Nodus Scan

Scan is the explorer part of the product family. The existing explorer indexes blocks and transactions and exposes a read-only JSON API. Its frontend offers block and transaction lookup, search, and address history.

The current transparent ledger exposes transaction amounts and address information. Scan displays indexed chain data from the witness cluster; it is not a wallet or an independent consensus validator.

Ledger V2, proofs, and ongoing integration

Ledger V2 includes modular domains, atomic block execution, resource metering, manifests, claims, and independent genesis. Current local code and integration scenarios go beyond the older public mirror: a V2 development chain can start from its own genesis. Consensus replacement and broader validation are ongoing.

The STARK prover/verifier is implemented. Proof-size and integration work remains; the ZK work was parked at its 7 August checkpoint pending the ledger and consensus foundations. Shielded payments and a compute market are not launched services.

What the security protects.

Private messages use Kyber1024 round-3 with AES-256-GCM; signatures use the Dilithium5 / ML-DSA-87 profile. The Kyber construction here predates ML-KEM/FIPS 203. These algorithm choices are not an independent audit or certification.

Message content
End-to-end encryption protects private message bodies. Public profiles and wall posts are intentionally shared.
Network metadata
Accepting nodes can observe IP addresses, timing, volume, and routing metadata. TCP channel encryption does not cover UDP discovery traffic or provide anonymity.
Local storage
SQLCipher encrypts local application databases. Android also uses Android Keystore for key wrapping. Secret-key operations run locally; public keys are shared for identity.

Nodus Engine, SDK & CLI

Nodus Engine is the native C foundation behind Connect. Applications call its asynchronous API for identities, contacts, messaging, groups, media, and wallets. Flutter integrates through FFI; the Nodus client SDK provides network access.

The existing CLI remains dna-connect-cli. Its dna command group exposes chain queries, balances, transfers, and development operations. It is also useful when testing integrations without the graphical app.
