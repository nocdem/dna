THE WORK, STEP BY STEPUpdated October 2026

Built over time.
Still moving forward.

From the first messenger to a resource network. Follow the dated development milestones, the work underway, and the next services taking shape.

  1. OCTOBER 2025

    The first messenger foundation

    DNA Messenger and its C library API were introduced, with key generation, encryption, and recovery as the starting point.

    IMPLEMENTED
  2. NOVEMBER 2025

    Distributed communication and mobile foundations

    DHT transport, signed profiles, group messaging, Android builds, and the Flutter/FFI foundation were added during November.

    IMPLEMENTED
  3. DECEMBER 2025

    The wallet grows across networks

    Ethereum, Solana, and TRON support joined the wallet, extending the existing Cellframe integration.

    IMPLEMENTED
  4. JANUARY 2026

    Native chain development begins

    The DNAC project was introduced for native transactions, wallet operations, and chain development.

    IMPLEMENTED
  5. FEBRUARY–MARCH 2026

    Nodus becomes the native network

    The pure C Nodus DHT replaced OpenDHT. Application integration and embedded witness infrastructure brought storage and the chain into the same server family.

    IMPLEMENTED
  6. MARCH–APRIL 2026

    Media storage and encrypted relay

    Persistent, resumable media uploads and endpoint-to-endpoint encrypted circuits expanded what applications could store and transport.

    IMPLEMENTED
  7. APRIL 2026

    Staking, delegation, and chain governance

    Validator and delegation flows, wallet screens, committee-voted parameters, epoch settlement, and supply checks were implemented.

    IMPLEMENTED
  8. JULY 2026

    Call signaling, C proofs, and Scan

    Call signaling and per-call key agreement, a C STARK prover/verifier, and the block explorer with its JSON API were added. Batched STARK work followed. Real-time call media remained a separate next step.

    IMPLEMENTED
  9. AUGUST 2026

    Ledger V2 takes shape

    Modular domains, atomic block execution, manifests and claims, and independent V2 genesis were implemented. The new ledger can start as its own development chain.

    IMPLEMENTED
  10. SEPTEMBER 2026

    Ledger V2 integration scenarios

    The V2 Genesis Protocol exercised multi-node startup, joining, recovery, restart, and epoch-boundary behavior. Broader consensus work continues.

    IMPLEMENTED
  11. SEPTEMBER 2026

    CometBFT consensus on devnet

    The CometBFT reference port is merged and runs the devnet, together with its peer-to-peer layer on port 4004. Scan reads this chain. Testnet preparation continues.

    IMPLEMENTED
  12. 30 SEPTEMBER 2026

    Nodus Chain testnet is live

    The chain moved from devnet to a public testnet on seven validator nodes, starting from a fresh genesis. There are no more resets: from now on, changes to the chain's rules take effect at an agreed block height. Its coin is NODUS.

    IMPLEMENTED
  13. OCTOBER 2026

    Four hard forks active on the testnet

    Rule changes take effect at an agreed block height. The first was set in the genesis document; the next three were switched on by validator votes: governance approvals weighed by voting power, block size bounded by the consensus limits, and on-chain names from block 3,151. Scan lists them on its Hard forks page.

    IMPLEMENTED
  14. 3 OCTOBER 2026

    Chain names in the web wallet and Nodus Connect

    Register a name for your Nodus address from the web wallet or Nodus Connect, and send to a name instead of a long address. A name is 3 to 36 English letters and digits, first come first served, one per address, and permanent. It costs 1,000 NODUS for 3 characters, 500 for 4, 100 for 5 and 1 for 6 or more; the price goes to the reward reserve, and validators can change it by vote.

    IMPLEMENTED
  15. 3 OCTOBER 2026

    Shared vaults in the web wallet and Nodus Connect

    A shared vault is a NODUS address that needs M of its N members to approve a payment. Create one from the web wallet or Nodus Connect with 2 to 7 members, chosen by chain name or ID; in Nodus Connect, members are told by message, add the vault with one tap, and propose and approve its payments.

    IMPLEMENTED
  16. OCTOBER 2026

    Scan: hard forks, throughput and paydays

    Scan lists every hard fork with its vote and effective block, finds a transaction by chain name, and shows the chain's transactions per second for the last minute and hour with a 24-hour chart, the next payday with an estimated date, past paydays and an estimated APY at the current block pace.

    IMPLEMENTED
  17. OCTOBER 2026

    A node in separate components — built, not yet on the live nodes

    The Nodus server can now also run as three separate processes: nodus-core, nodus-storage and nodus-witness, installed from one tar.gz package with an install script. The single combined server stays the default, and the live testnet nodes still run it.

    IMPLEMENTED
  18. 4 OCTOBER 2026

    Block pruning and archive nodes — live, switched on node by node

    Nodus 0.23.18 runs on all seven testnet nodes. A pruned validator keeps the last 7 paydays (120,960 blocks) plus the link to genesis; an archive node keeps every block. Every node now drops the duplicate “seen commit” copy, so chain storage grows more slowly. Pruning is switched on on one node first; the others follow after it has been checked.

    IMPLEMENTED
  19. SEPTEMBER 2026 / NOW

    Nodus in the browser

    The web wallet sends, receives and delegates NODUS on the testnet through the nodes' WebSocket entry, sends to a chain name, and keeps an address book for every network it sends on. Nodus Connect, the wallet and messages in one web app, is open as a preview. Each contact has one name — the chain name, or else the profile name — with the ID shown underneath. Connect opens at once from what the device keeps (contacts, conversations, names) and connects in the background; sending waits until it is connected.

    IN PROGRESS
  20. OCTOBER 2026 / NOW

    NODUS airdrop for CPUNK holders

    The airdrop page explains which CPUNK counts and how a share is worked out. Registering and claiming from Nodus Connect are coming; the start will be announced.

    IN PROGRESS
  21. NEXT

    Lower validator stake and node roles

    A validator's own bond drops from exactly 10 million NODUS to at least 2 million; more can be delegated to itself. Storage (1 million), compute (1 million) and bandwidth (500,000) roles get their own stake, and these amounts can be changed by vote. The same upgrade caps the voting power counted for one validator, starting at 10%, and separates the owner's key from the node's key. It takes effect only with a hard fork that validators vote in.

    PLANNED
  22. NEXT

    Storage role reward

    Nodes that register in the storage role with a stake of 1 million NODUS earn an equal share from the Storage pool when validators confirm that they serve stored data. Validators do not earn storage rewards; a storage node and a validator can be the same machine. The design was approved on 4 October 2026 and is being built; it is switched on later by an on-chain vote.

    PLANNED
  23. NEXT

    Storage capacity market

    Buy space for personal files and application data through a storage marketplace built around the Nodus network.

    PLANNED
  24. NEXT

    Bandwidth for VoIP and beyond

    Extend the relay foundation into a bandwidth service for real-time calls and other network traffic.

    PLANNED
  25. NEXT

    Compute market

    Bring STARK proof-generation jobs and AI-training workloads to a market for compute capacity.

    PLANNED

Dates record development milestones in the project history. Completing a component does not mean every related service has launched. Planned services have no announced launch date.
